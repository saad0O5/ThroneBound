ThroneBound Project Report

1. Introduction
This report describes the current implementation of ThroneBound, a desktop strategy card game built with JavaFX and Maven. The game is designed around lane-based combat, card selection, and turn-based play. The current codebase includes the main gameplay screens, user profile handling, and basic match flow.

2. Project Scope
The project currently supports:
- Login and user profile management.
- Main menu navigation.
- Deck building with a fixed-size card list.
- Host/join lobby screens.
- Match screen with board lanes, hand cards, and turn actions.
- Results screen showing match outcome.

This implementation is focused on desktop behavior and basic game structure rather than final polished art or complete networked multiplayer verification.

3. Design and Architecture
The code is organized into separate packages to keep responsibilities clear:
- `cards`: card definitions, factions, cost model, and deck handling.
- `engine`: game state, players, lanes, resources, combat and win conditions.
- `gui`: screen classes, UI helpers, and app startup.
- `network`: client and server messaging for host/join behavior.
- `persistence`: player profiles, match history, and profile storage.

Key architectural choices:
- `ThroneBoundApp` manages the application lifecycle and scene setup.
- A new `SceneManager` singleton keeps the game on one JavaFX scene and swaps screen roots.
- The model layer is kept separate from JavaFX-specific UI code.
- `GameState` includes board lanes, graveyards, resources, and turn handling.

4. UI and Desktop Behavior
The application is built for desktop use:
- JavaFX UI with a dark fantasy theme.
- Minimum window size is set for usability, and the window is resizable.
- CSS styling is centralized in `src/main/resources/gui/styles.css`.
- Screens are created in Java classes rather than FXML.
- A confirmation dialog appears if the user tries to quit during an active match.

5. Game Logic Implementation
The main game logic is implemented in the engine package:
- `GameState` manages turns, player life, lane placement, and card play.
- Cards are modeled with `Card` subclasses and cost structures.
- Resources are checked before card play, and the match cannot continue after `matchOver` is set.
- The deck builder enforces an exact deck size.
- The match screen allows players to select cards and play them to lanes.

6. Status and Limitations
Completed features:
- Screen navigation and basic UI.
- Deck selection and deck size enforcement.
- Match play with life tracking, lane state, and resource usage.
- One-stage app startup and screen root swapping.

Remaining or partial work:
- Full FXML-based MVC structure is not implemented.
- Networked match flow exists in code but has not been validated end-to-end in this report.
- Some desktop features and animations remain incomplete.
- The card collection and settings screens are not present in the current code.

7. Challenges
The main challenges in this implementation were:
- Keeping game rules in the engine layer while still providing responsive UI updates.
- Aligning the existing code structure with a desktop-focused navigation model.
- Working without a complete build environment to run Maven commands.

8. Conclusion
The current project implementation provides a working foundation for ThroneBound. It demonstrates basic desktop JavaFX navigation, core game state management, and the required main screens. More work is needed for full multiplayer testing, final UI polish, and a complete report package.
